# Orders filter UI v2

Followup to web PR310 and server filter-v2 followup to PR467; existing date/Copy PRs remain unchanged. New UI generates filterVersion=2. No migrations, Shopify collection, saved view, mutation buttons, mode/feature-flag changes or deployment are included.

The single filter row contains selected condition chips, Add filter and Clear all. There is no Orders search input; an incoming search query remains visible as a removable chip for URL compatibility. Eight independent dimensions use concise display labels: Stop type; Delivery status; Order date; Delivery date (scheduled delivery/pickup range, actual weekday, or no date); Payment; Fulfillment; Cancellation; Area. Internal keys and predicates are unchanged. Panels anchor to the clicked chip or Add filter, include individual Clear, and fit the viewport. Enum choices remain stable. Both date panels immediately show a range calendar; presets are shortcuts and Weekday reveals the optional weekday constraint. There are no From/To date inputs. Completed ranges and presets apply and close immediately; checkbox/radio drafts apply and close with the panel Add filter button. Dismissing a panel discards unapplied changes. There is no fixed State/date row or separate Pickup day control.

Different dimensions AND; multiple values within one dimension OR. A date range includes both endpoints. Presets use the supplied store-local day, not the browser timezone. No-date is exclusive with range/weekdays; selecting weekdays never changes the service type. Chips remove only their own dimension. Clear all also clears search, cursor/page/watermark, manual selection and frozen selection request state, returning to the unfiltered first page. Selection invalidates on any query change.

Default is unfiltered all history, including cancellations and missing data. Cancelled orders retain existing action eligibility restrictions. Map keeps existing coordinate/limit omissions. New UI does not classify pickup deadline expiry as Delivered/Complete: it displays Pickup period ended. V2 table rows, facets/map and selection use the same authenticated server predicate/filter hash; paginated rows are not filtered again in the browser. The BFF repeats URL array keys and preserves JSON arrays; it replaces client timezone with authenticated store IANA metadata. A nonpaginated v2 loader also returns only the server cohort, preventing unfiltered Shopify/background-sync rows from widening it.

Legacy URLs without filterVersion retain the old State/raw-weekday predicates. The bar discloses that selecting a new condition replaces legacy conditions; clearing returns to v2. Unsupported versions fail explicitly. Legacy helper exports remain for compatibility tests; the old fixed controls are removed. No current filters are silently translated into different v2 concepts.

Local checks cover URL/repeated-array transport across all BFF query endpoints and snapshot POST, chip deletion, clear-all, independent weekdays/type, date presets, default/legacy contracts, Korean labels and rendered component content. The actual EasyRoutes/CLEVER Safari screens were inspected read-only. Local browser clicks on the real Orders component with a synthetic loader verified both calendars, atomic date ranges, automatic close, draft/apply/cancel, per-filter clear, compact chips and adjacent popovers. Production data/result counts and mobile devices are outside this local validation; see [interaction review](../ui/orders-filter-interaction-review.md).

Release only after separate approval: deploy additive server v2 before new web. Restore/revert web first on rollback, then server if needed; retain dependency date/Copy fixes by reverting only filter followup commits. No DB restore is necessary.
